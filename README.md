# Калькулятор GPU для MIP

Сколько GPU NVIDIA нужно, чтобы запустить LLM на MIP (платформа управляемого инференса), сколько токенов в час это даст и сколько стоит один токен в рублях.
Написан на Go без внешних зависимостей. Есть веб-интерфейс, REST API и MCP-сервер для агентов.

## Запуск

```bash
go build -o gpucalc . && ./gpucalc            # http://localhost:8080
./gpucalc -addr :9000 -config /etc/mip/gpu.json
./gpucalc -stdio                               # MCP через stdio
docker build -t mip-gpucalc . && docker run -p 8080:8080 -v $PWD/data:/data mip-gpucalc
```

Тесты: `go test ./...`

## Как считается

**Память.** На каждой GPU должно поместиться `веса/(TP×PP) + KV/шарды + state + накладные ≤ VRAM × доля VRAM`.
- Веса — по размеру официального чекпоинта (точность `native`) или `параметры × байт формата`.
- KV на токен: у GQA `2 × слоёв с KV × KV-голов × размер головы × байт`, у MLA `слоёв × (ранг + RoPE) × байт`, плюс индексер DSA.
- KV всего: `KV на токен × контекст × параллельных запросов`. У MLA он дублируется на каждом TP-ранге.
- State линейного внимания (гибриды Qwen3.8) — фиксированный объём на запрос.
- Раскладки перебираются по возрастанию: сначала TP внутри ноды, затем целые ноды с PP.

**Скорость (roofline).**
- Шаг decode: `max(чтение HBM, вычисления) + задержка на слой × слоёв`.
- Чтение HBM: веса, которые реально прочитаны за шаг (у MoE доля экспертов `1 − (1 − k/E)^batch`), плюс KV всех запросов.
- Prefill упирается в вычисления: `2 × активные параметры + 4 × слоёв × hidden × средняя позиция` FLOP на токен. У разреженного DSA позиция ограничена top-k.

**Стоимость в рублях (совмещённый режим).**
- На один запрос реплика тратит `вход / скорость prefill + выход / скорость decode` секунд.
- `токенов в час = запросов в час × токенов на выходе`
- `₽ за токен = (₽/час за GPU + ₽/час за сеть) / токенов в час`. Показываются также ₽ за 1 млн токенов, раздельно за вход и выход, и ₽ за запрос.

**Prefill / Decode (вкладка и инструмент `pd_disaggregation`).**
- Пул decode задаётся параметрами формы. Пул prefill подбирается так, чтобы загрузить decode: `инстансов = ⌈запросов/с × вход / скорость инстанса⌉`.
- KV одного prompt (`вход × KV на токен + state`) передаётся по выбранной сети: NVLink (только внутри ноды), InfiniBand или RoCE с RDMA, либо TCP без RDMA (×1,5 на копирование через память хоста).
- Считаются время передачи, загрузка сети (если она выше 100%, пропускная способность урезается), TTFT и ₽ за 1 млн выходных токенов, включая цену сети за ноду.
- Альтернативы: каждый тип GPU под prefill × каждая сеть. Порядок сортировки: укладывается в цель TTFT → дешевле за 1 млн токенов.
- Итог проверен тестами. У MoE с коротким prompt дешевле совмещённый режим. У плотной 405B с prompt 32K раздельные пулы экономят около 35%.

Всё это оценка для планирования, а не замена нагрузочному тесту. Подогнать модель под реальные замеры можно коэффициентами эффективности в настройках платформы.

## Настройка

Всё хранится в `config.json` (при первом запуске создаётся из `config.default.json`).
Править можно вручную в файле (изменения подхватываются без перезапуска), во вкладке «Настройки», через API или MCP.

- `platform` — доля VRAM, накладные, размеры TP, эффективность HBM, вычислений и prefill, задержка на слой, значения по умолчанию.
- `gpus` — VRAM, пропускная способность HBM, TFLOPS, форматы, **цена ₽/час**, доступное количество.
- `interconnects` — Гбит/с на GPU, эффективность, RDMA, задержка, **₽/час за ноду**.
- `models` — архитектура: параметры, эксперты, KV, state, hidden, top-k, чекпоинт, ссылка на источник.

> **Цены GPU и сети в `config.default.json` — заглушки.** Подставьте тарифы MIP.

Данные моделей взяты из `config.json` и карточек моделей на Hugging Face (октябрь 2026). Сверка с вендорами закреплена тестами: GLM-5.2 в FP8 → 8×H200 и 8×B200 для контекста 1M (рецепт vLLM), DeepSeek-V4.1-Flash → 4×GB300 (карточка NVIDIA).

## API

| | |
|---|---|
| `GET/PUT /api/config` | весь конфиг |
| `POST /api/calculate` | `{model, gpu, precision?, kv_dtype?, context_len?, concurrency?, replicas?, mem_util?, input_tokens?, output_tokens?, interconnect?, ttft_slo_ms?}` |
| `POST /api/compare` | то же без `gpu` — по всем GPU |
| `POST /api/pd` | совмещённый режим, раздельный P/D и альтернативы |
| `POST /api/matrix` | модели × GPU |
| `GET /api/models/metrics` | ключевые метрики моделей |
| `PUT /api/models`, `DELETE /api/models/{id}` | добавить/обновить или удалить модель |
| `PUT /api/gpus`, `DELETE /api/gpus/{id}` | добавить/обновить или удалить GPU |

## MCP

Streamable HTTP: `http://localhost:8080/mcp`, либо stdio (`-stdio`).

```bash
claude mcp add --transport http mip-gpu-calc http://localhost:8080/mcp
```

Инструменты: `list_models`, `model_metrics`, `list_gpus`, `list_interconnects`, `get_platform`, `calculate`, `compare_gpus`,
`recommend`, `pd_disaggregation`, `matrix`, `upsert_model`, `upsert_gpu`, `delete_model`, `delete_gpu`.
